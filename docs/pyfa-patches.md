# Pyfa patch ledger

The `pyfa-parity` branch supplies the fitting engine for Rufa. The previous comparison pin before the M8.24 integration was `e39ef83669c027d367cb943d08ab452088d674df`, tagged `pyfa-v2.70.0-firbolg-reload`. It shares base `c9f066f34703eebe388fa17f739300b75654d55d` with upstream. The M8.24 replay starts at upstream `6ca148e1c7a45645773418fde9fcb399c358822f`, the master head checked on 2026-11-21. The histories before replay contained 15 published fork-only and 39 upstream-only commits. The initial published M8.24 integration baseline is `6afcaae2cc9c27b1a7c163d3bbc1748273117da9`. ## Updating this ledger

For a new patch, record the first release milestone, originating commit, affected upstream code, and smallest test that fails without it. When upstream passes that test, remove the equivalent local hunk on the integration branch and replay the affected workflows. Mark the row retired with the replacing upstream revision and first qualified Rufa pin. For a mixed patch, update the affected rows independently. Keep build tuples, release decisions and cross-product pilot results in the [development repository](https://github.com/naivej/rufa_dev).
